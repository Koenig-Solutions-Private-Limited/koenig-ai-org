## Item 3 — MCP vs A2A: The Protocol Boundary That Decides Your Multi-Agent Security Model

**Perishability:** MEDIUM — MCP 1.0 in production (spec `2025-11-25`), RC for `2026-07-28` spec already circulating; A2A adoption accelerating with Google/Azure endorsement; content window ~4–6 weeks before saturation.

**Blog angle:** "MCP or A2A? The Protocol Boundary That Matters for Multi-Agent Security"

**Why newsworthy:**
- Developers are conflating MCP and A2A; the distinction is architectural, not syntactic: MCP is agent-to-tool (vertical), A2A is agent-to-agent (horizontal peer delegation).
- Tool proxying pattern: Agent B wraps its MCP server as a capability in its A2A Agent Card; Agent A delegates via A2A without ever holding MCP credentials for Agent B's tools. This is the canonical multi-agent isolation pattern for 2026.
- Resource injection (MCP Resources) is the secondary pattern for context scoping: inject schemas/prior research as Resources into specialist scope before A2A dispatch — preserves role boundaries.
- Critical security gap: proxied tool calls introduce confused-deputy risk. Mitigation requires per-tool OAuth scopes, short-lived tokens, and a gateway proxy (Pomerium, Gravitee, Stytch patterns documented).
- MCP Resources are often overlooked but are the right primitive for read-only context injection (vs Tools, which carry action/privilege risk).
