# Plan: align course discovery for sitemap and llms.txt

## Goal
Make Academy discovery surfaces enumerate the same ten renderable course pages that `/catalog` and `/learn/[slug]` already expose. Success means `/sitemap.xml`, `/llms.txt`, and the catalog/static-course route source all derive course pages from one named helper, and every generated `/learn/{slug}` in scope resolves locally with HTTP 200.

The ten expected KOEA-2457 slugs are: `claude-opus-47-from-zero`, `claude-tool-use-from-zero`, `cursor-composer-2`, `gemini-enterprise-agents`, `mcp-from-first-principles-to-production`, `migrating-custom-gpts-to-chatgpt-workspace-agents`, `multi-agent-orchestration-a2a`, `openai-agents-sdk-mastery`, `picking-a-frontier-model-2026-q2`, `production-agents-claude-agent-sdk-mcp-connector`.

## Context
- Files to read first: `learnova-academy/src/lib/courses.ts:186-253`, `learnova-academy/src/app/catalog/page.tsx:1-50`, `learnova-academy/src/app/learn/[slug]/page.tsx:42-47`, `learnova-academy/src/app/sitemap.ts:1-29`, `learnova-academy/src/app/llms.txt/route.ts:1-31`.
- Relevant prior work: PR #39 (`https://github.com/Koenig-Solutions-Private-Limited/learnovaBeast/pull/39`) is closed unmerged; it only changed sitemap from `listPublishableCourses()` to `listAllCourses()` and missed `llms.txt`.
- Constraints: use `learnovaBeast/learnova-academy` on `academy/redesign-v1`; no Convex deploys; no other portal changes; do not mask baseline lint/build/runtime issues (`GlossaryPopover.tsx:34`, prior prerender failures, missing `browser-use`).

## Approach (1 chosen, alternatives rejected)
**Chosen**: Add `listDiscoverableCourses()` in `src/lib/courses.ts` as the explicit course source for public discovery and static course surfaces. For this ticket it should return the same vault-backed set as `listAllCourses()` because those are the courses that have `outline.md`, are rendered in catalog, and are generated by `/learn/[slug]`; then update sitemap, `llms.txt`, catalog, and `generateStaticParams()` to use the named helper so future filtering changes happen in one place.

**Rejected**: Change only sitemap and `llms.txt` to `listAllCourses()`; it fixes the symptom but leaves three independent call sites with no named contract. **Rejected**: Broaden `PUBLISHABLE_COURSE_STATES`; the current vault statuses include values like `awaiting-g0` and `g0-blocked`, so widening publishability would blur editorial status with route discoverability and may affect unrelated consumers of `listPublishableCourses()`.

## Steps (Executor follows in order)
1. Start from `origin/academy/redesign-v1` in `learnovaBeast/learnova-academy` and keep the PR base set to `academy/redesign-v1`.
2. In `src/lib/courses.ts`, export `listDiscoverableCourses()` immediately after `listAllCourses()` and have it return the same sorted vault course list; add a short comment that it is for routes known to render via `generateStaticParams()`, not editorial publish state.
3. In `src/app/catalog/page.tsx` and `src/app/learn/[slug]/page.tsx`, replace `listAllCourses()` imports/usages with `listDiscoverableCourses()` so catalog, static params, sitemap, and llms share the same helper.
4. In `src/app/sitemap.ts`, replace `listPublishableCourses()` with `listDiscoverableCourses()` for `/learn/{slug}` routes only; leave blog, author, glossary, vendor, and capability routes unchanged.
5. In `src/app/llms.txt/route.ts`, replace `listPublishableCourses()` with `listDiscoverableCourses()`, update the `courseTagline` type, and correct the top comment so it describes discoverable/renderable course pages rather than publishable status.
6. Add a lightweight Node assertion script under `learnova-academy/scripts/` that builds/reads the helper output and route handlers as needed to confirm the ten expected slugs appear in both discovery files and that no expected slug is missing.
7. Prepare the PR handoff with base `academy/redesign-v1`, reference KOEA-2457, and call out that PR #39 was superseded because it covered only sitemap.
