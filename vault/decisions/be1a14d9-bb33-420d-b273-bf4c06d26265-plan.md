# Plan: singleflight `opencode models` discovery to stop the concurrent-wake stampede

## Goal

Six (or any N) simultaneous `opencode_local` wakeups that arrive during a cold cache must result in **exactly one** spawn of `opencode models`. All in-flight callers receive the same resolved model list (or the same rejection) and the TTL cache is populated exactly once. After the in-flight discovery settles, the cache governs subsequent calls until the existing 60s TTL expires; if the discovery failed or returned a non-cacheable result, the next caller after settlement triggers a fresh discovery.

Success is observable as:

1. Under 6 concurrent callers to `discoverOpenCodeModelsCached`, the underlying `discoverOpenCodeModels` (which runs the `opencode models` child process) is invoked exactly **1** time.
2. All 6 callers resolve with the same `AdapterModel[]` reference (or equivalently-shaped array) and none observe the 20s `MODELS_DISCOVERY_TIMEOUT_MS` timeout from a thundering herd.
3. If the single discovery throws (e.g. binary missing, timeout), all 6 callers reject with the **same** error and the in-flight entry is cleared so the 7th call (after settlement) triggers a new discovery.
4. Existing cache hardening still holds: only results with ≥2 providers are written to the TTL cache; the `ensureOpenCodeModelConfiguredAndAvailable` missing-model retry continues to call uncached `discoverOpenCodeModels` directly (Step 4 below).

### Symptom origin

`discoverOpenCodeModelsCached` checks the cache, finds nothing, then awaits `discoverOpenCodeModels`. Between the cache miss and the cache write (around L168-179), N concurrent callers all see the miss and all spawn their own child process. With six concurrent wakeups + a 20s timeout cap on the child, the OS scheduler + opencode's own slowness can push individual spawns past the per-call timeout, so all six surface "`opencode models` timed out after 20s." The cache hardening (KOEA cache flicker fix) prevents the wrong-result lock-in but does nothing against the stampede.

## Approach (1 chosen, 2 rejected)

**Chosen — module-level `Map<string, Promise<AdapterModel[]>>` singleflight, key = `discoveryCacheKey`, cleared in a `finally`.**

The in-flight map stores the shared promise of the currently running discovery for a given `(command, cwd, hashed-stable-env)` key. A cold-cache caller:

1. Re-checks the TTL cache (unchanged).
2. Looks up the inflight map for `key`. If present, awaits the existing promise and returns its resolution (or rejects with its rejection — failures are shared, not retried in parallel).
3. If absent, creates a new promise by calling `discoverOpenCodeModels(...)`, stores it in the inflight map *synchronously before the first `await`*, and registers a `.finally(() => inflight.delete(key))` to clear the slot regardless of success/failure.
4. After the underlying discovery resolves, performs the existing ≥2-providers cache-write gate, then returns the models.

This makes the cache-miss path coalesce N concurrent callers into one child process, preserves the existing cache hardening, and keeps failure-mode behaviour predictable (shared error, then full retry).

**Rejected — also wrap `ensureOpenCodeModelConfiguredAndAvailable`'s fresh-retry call in singleflight.** The retry at `models.ts:204` already bypasses cache intentionally to defend against a partial result that passed the ≥2-providers gate but is missing the configured model. Coalescing the retry would mean a follower that hit a partial-result cache and a leader that hit a stale-but-cache-valid result could share an unrelated retry. The retry is conditional + rare, and wrapping it changes semantics. *Decision:* leave the retry alone; the parent ticket is scoped to the cached path.

**Rejected — promote the TTL cache to also store rejections for a short negative-cache window.** Caching errors for, say, 5s would also prevent the stampede on failure and is what node-cache libraries default to. *Reason for rejection:* failures here include "command not found" (semi-permanent until user installs opencode) and "opencode models timed out" (transient OS pressure). A negative cache window has to pick one, and the parent ticket explicitly asks for "singleflight," not "negative cache." Singleflight already prevents the stampede on failure (all 6 share the same in-flight promise) without committing to a window. *If* a follow-up shows that immediately retrying a known-broken `opencode` binary on the next wake is still expensive, propose negative-cache then.

1. **Add the in-flight map.** In `packages/adapters/opencode-local/src/server/models.ts`, immediately below the existing `discoveryCache` (L22), add:

2. **Rewrite `discoverOpenCodeModelsCached` body** (L159-182) to add the singleflight check between the TTL-cache check and the `discoverOpenCodeModels` call. Target shape (executor adapts to current formatting):

   ```ts
   export async function discoverOpenCodeModelsCached(input: { command?: unknown; cwd?: unknown; env?: unknown; } = {}): Promise<AdapterModel[]> {
     const command = resolveOpenCodeCommand(input.command);
     const cwd = asString(input.cwd, process.cwd());
     const env = normalizeEnv(input.env);
     const key = discoveryCacheKey(command, cwd, env);
     const now = Date.now();
     pruneExpiredDiscoveryCache(now);

     const cached = discoveryCache.get(key);
     if (cached && cached.expiresAt > now) return cached.models;

     const existing = inflightDiscovery.get(key);
     if (existing) return existing;

     const pending = (async () => {
       const models = await discoverOpenCodeModels({ command, cwd, env });
       // Cache hardening preserved: only cache when result looks complete (≥2 providers).
       if (distinctProviderCount(models) >= 2) {
         discoveryCache.set(key, { expiresAt: Date.now() + MODELS_CACHE_TTL_MS, models });
       }
       return models;
     })();

     inflightDiscovery.set(key, pending);
     pending.finally(() => {
       // Always clear, regardless of success or failure. Failures are shared with
       // all current followers but never linger to block the next caller's retry.
       inflightDiscovery.delete(key);
     }).catch(() => { /* swallowed — error already propagates via the awaited `pending` */ });

     return pending;
   }
   ```

   Notes for executor:
   - The `inflightDiscovery.set(key, pending)` MUST happen synchronously after the promise is constructed and before any `await` on `pending`. The IIFE pattern above achieves that because `pending` is a Promise reference, not yet awaited at the `set` line.
   - The `.finally(...).catch(...)` chain is **not** awaited — it runs as a side-effect to keep the map clean. The outer `return pending` is what the caller awaits.
   - The bare `.catch(() => {})` on the side-effect chain prevents an unhandledRejection warning from the side-effect promise; the original rejection still surfaces through the awaited `pending`.

## Risk

- **Side-effect promise unhandled-rejection.** Node logs `UnhandledPromiseRejection` if a promise chain rejects without a `.catch`. The `.finally(...).catch(() => {})` pattern in Step 2 covers this. *Mitigation:* during executor work, run the failure-case test in isolation under `pnpm exec vitest run --reporter verbose` and confirm no `UnhandledPromiseRejection` is logged.
- **Lost retry on transient failure.** Shared rejections mean that a transient OS hiccup affecting one of six concurrent wakeups now fails all six. *Counter:* without singleflight, all six were already failing because all six were spawning their own timed-out child. The new behaviour is strictly better — one process fails, six callers see the failure quickly instead of waiting 20s each. The in-flight clear-on-settle preserves the retry budget for the next wake.
- **Module-private singleton races with vitest module reuse.** Vitest reuses module state across tests in the same file. The `afterEach` cleanup (`resetOpenCodeModelsCacheForTests` + `__setDiscoveryImplForTests(null)`) must run before each new test seeds its own fake. *Mitigation:* the test plan in Step 5 explicitly resets both maps and the discovery seam in `afterEach`.
