# Plan: `notebooklm-driver` Paperclip adapter wrapping the `open-notebook` API

## Goal

Ship a registered external Paperclip adapter of type `notebooklm_driver` that, given a vault path to a markdown/PDF source and a capability choice, drives the already-running `open-notebook` HTTP service at `http://open-notebook:5055` and commits the resulting artifact (mp3 podcast or markdown insight) back to a specified vault path. After this lands:

- `GET /api/adapters` lists `notebooklm_driver`
- A test agent configured with this adapter, given `vault/blogs/notebooklm-as-a-learning-system/draft.md` and `capability=generate_podcast`, `episode_profile=solo_expert`, produces a playable `podcast.mp3` under a vault test path within < 5 minutes
- The same agent round-trips four insight types (`mind_map`, `faq`, `study_guide`, `briefing`) to four markdown files under the same vault test path
- Cost stays at $0 incremental Paperclip cost; OpenAI billing flows through the existing key stored in open-notebook's credentials DB

### Live open-notebook surface (verified 2026-05-12 via `host.docker.internal:5055`)

| Endpoint | Use | Notes |
|---|---|---|
| `POST /api/sources` (`multipart/form-data`) | Upload the source content | Fields: `type` (str), `content` (str, raw text), `title`, `notebook_id?`, `transformations?`, `embed`, `async_processing="false"`. | `POST /api/podcasts/generate` | Kick off podcast | Body: `{episode_profile, speaker_profile, episode_name, content?, notebook_id?, briefing_suffix?}`. Returns `{job_id, status, ...}`. |
| `GET /api/podcasts/jobs/{job_id}` | Poll podcast job | Status values include `queued`, `running`, `completed`, `failed`. Result carries `episode_id` once complete. |
| `GET /api/podcasts/episodes/{episode_id}/audio` | Stream the mp3 | Binary body; save to disk. |
| `POST /api/sources/{source_id}/insights` | Kick off transformation insight | Body: `{transformation_id, model_id?}`. Returns 202 with `{command_id, source_id, transformation_id, status: "pending"}`. |
| `GET /api/commands/jobs/{command_id}` | Poll insight job | Generic `CommandJobStatusResponse`: `status`, `result`, `error_message`, `progress`. |
| `GET /api/sources/{source_id}/insights` | List finished insights for a source | Pull the latest one whose `transformation_id` matches the request. |
| `GET /api/transformations` | List existing transformations | Default seed has: `Analyze Paper`, `Dense Summary`, `Key Insights`, `Reflections`, `Simple Summary`, `Table of Contents`. **No** `mind_map`, `faq`, `study_guide`, or `briefing` exists. |
| `POST /api/transformations` | Create custom transformation | Must be invoked once at install time to seed the four named transformations. |
| `GET /api/episode-profiles` | List episode profiles | Confirmed live: `business_analysis`, `solo_expert`, `tech_discussion`. |
| `GET /health` | Reachability probe | Used by `testEnvironment()`. |

### Constraints

- **Container DNS**: from `paperclip-server`, open-notebook is at `http://open-notebook:5055`. The host-side `localhost:5055` exists only outside the network. Default the base URL to `http://open-notebook:5055`, overridable via `OPEN_NOTEBOOK_BASE_URL` env.
- **Auth**: `OPEN_NOTEBOOK_API_KEY=local-dev` is present in the agent env. Send as `Authorization: Bearer ...` once we confirm whether open-notebook requires it — `GET /api/auth/status` decides at runtime. Skip auth if `auth_required=false`.
- **No upstream edits**: every file lives in our adapter package surface or under `~/.paperclip/adapter-plugins.json`. Do not touch `packages/adapters/openrouter-direct/`, `server/`, or `cli/` core files.
- **Budget**: per-task $1 cap. This plan-only run logs ~$0.20. Implementation should fit comfortably inside $2 across Executor + Code Reviewer + QA.

## Approach (1 chosen, alternatives rejected)

**Chosen — external adapter package at `packages/adapters/notebooklm-driver/`, registered via local-path entry in `~/.paperclip/adapter-plugins.json`, dispatch model encoded as `config.capability`.**

The adapter is a thin HTTP client. Its `execute()` reads three things from `ctx.config` and the task prompt:

1. `capability` ∈ {`generate_podcast`, `generate_mind_map`, `generate_faq`, `generate_study_guide`, `generate_briefing`}
2. `source_path` — absolute path inside the agent's vault read mount (defaults to `${PAPERCLIP_VAULT_DIR}` or the agent's project workspace dir)
3. `output_dir` — vault-relative path for artifacts

It uploads the source content as a single `POST /api/sources`, kicks off the requested job, polls until done, downloads the artifact, writes to disk, and returns a structured `AdapterExecutionResult` with `summary` + `resultJson` listing the written paths.

Why this shape:

- **`execute()` is the natural contract** — the server runs this whenever an agent is dispatched, and `AdapterExecutionResult` already carries `resultJson` for arbitrary structured output.
- **Capability is config (not a tool catalog)** — avoids inventing a custom tool-calling protocol; each agent instance is wired for one capability, mirroring how `learnova-publish` and `obsidian-vault` adapters work in the same monorepo.
- **`packages/adapters/` mirrors upstream layout** — Paperclip's plugin loader expects a package directory with `package.json` + `paperclip.plugin.json`; placing it inside the existing pnpm workspace keeps `pnpm install` discovery free (the `/app/adapters/notebooklm-driver` placeholder remains an empty marker but is **not** the code home; the registration uses `localPath` pointing at the workspace package).

**Rejected:**

- *Implement as `claude-local` tool-calling MCP* — heavier (MCP server in a sidecar), and we lose adapter-level discoverability in `GET /api/adapters`. Two agents already exist; keep this one inside the adapter contract for parity.
- *Single capability "drive_notebooklm" with a JSON prompt schema* — moves dispatch into prompts, which a model-driven agent could fail. Capability-as-config gives the orchestrator deterministic control.
- *Generate insights via the chat endpoint (`POST /api/chat/execute`)* — bypasses the transformation registry and ties output quality to whatever model is currently default. The `/insights` route is purpose-built and returns clean structured markdown.
- *Use Claude Code's `notebooklm` Playwright skill instead* — the issue explicitly says do BOTH (skill as fallback). This plan covers track (A) only; track (B) is owned by the existing claude_local skill and needs no engineering.

## Steps (Executor follows in order)

### A. Package scaffold (no business logic yet)

1. **Create the package directory** `packages/adapters/notebooklm-driver/` with:
   - `package.json`: name `@paperclipai/adapter-notebooklm-driver` (private), `type: "module"`, `exports`: `"."` → `./src/index.ts`, `"./server"` → `./src/server/index.ts`, `"./ui"` → `./src/ui/index.ts`, `"./cli"` → `./src/cli/index.ts`. Dependencies: `@paperclipai/adapter-utils workspace:*`, `@paperclipai/shared workspace:*`. Dev: `typescript`, `@types/node`.
   - `tsconfig.json` extending the workspace root.
   - `paperclip.plugin.json` modeled on `packages/adapters/openrouter-direct/paperclip.plugin.json` — `type: "adapter"`, `id: "notebooklm-driver"`, `name: "NotebookLM Driver"`, `version: "0.1.0"`, `entry.adapter: "./src/index.ts"`, `configSchema` describing the fields below.
   - `README.md` — installation + smoke-test invocation.

2. **Create `src/index.ts`** — root metadata, dependency-free:
   - `export const type = "notebooklm_driver" as const;`
   - `export const label = "NotebookLM Driver";`
   - `export const agentConfigurationDoc = "..."` — explain capabilities, source_path, output_dir, env requirements.
   - Capability list constants (string union).
   - Declare interfaces: `NotebookLmDriverConfig { capability, sourcePath, outputDir, episodeProfile?, speakerProfile?, episodeName?, briefingSuffix?, model?, baseUrl?, apiKey? }`.

3. **Create `src/server/index.ts`** — server barrel re-exporting `execute`, `testEnvironment`, `getConfigSchema`, `models` (static list of capabilities). Mirror the openrouter-direct barrel doc-comment style.

4. **Create `src/server/server-index.ts`** — exposes `createServerAdapter()` returning the fully assembled `ServerAdapterModule`. This is what `plugin-loader.ts:148` looks for. **Do not skip this**: the validator in plugin-loader rejects modules without `createServerAdapter`.

### B. HTTP client + capability dispatch

5. **`src/server/client.ts`** — small `fetch`-based wrapper:
   - `class OpenNotebookClient { constructor({ baseUrl, apiKey, fetchImpl }) }`
   - Methods: `health()`, `createTextSource({ content, title, notebookId? })` (multipart), `generatePodcast(body)`, `getPodcastJob(jobId)`, `streamPodcastAudio(episodeId)` → Response, `createSourceInsight(sourceId, transformationId)`, `getCommandJob(jobId)`, `listSourceInsights(sourceId)`, `listTransformations()`, `createTransformation(body)`, `listEpisodeProfiles()`.
   - Polling helper `pollUntilDone(jobId, kind: "podcast"|"command", { intervalMs=3000, timeoutMs=300_000 })` — returns the final status payload, throws on timeout or `status=failed`.
   - All methods log via `ctx.onLog("stdout", JSON.stringify({phase, op, status}))` so the run viewer shows progress.

6. **`src/server/transformations.ts`** — seed the four custom transformations on first execution if missing:
   - `mind_map` → prompt: "Produce a hierarchical Markdown mind map of the input. Root = title. 3–5 top-level branches, 2–4 sub-branches each, leaf bullets <= 15 words."
   - `faq` → prompt: "Generate 10 frequently-asked-questions and their concise answers grounded in the source. Output as `### Q.<n>` then answer paragraphs."
   - `study_guide` → prompt: "Produce a study guide with sections: Learning Objectives (5 bullets), Key Concepts (definitions), Worked Examples (2), Self-Check Questions (5)."
   - `briefing` → prompt: "Write a 400-word executive briefing for a busy stakeholder. Cover: what changed, why it matters, what to do next."
   - `ensureTransformations(client) → Record<capability, transformation_id>` — idempotent: `GET /api/transformations`, create only the missing four by stable `name`, cache the resulting IDs on a module-level singleton keyed by base URL.

7. **`src/server/execute.ts`** — the contract entry point:
   - Validate `ctx.config` against `NotebookLmDriverConfig` (Zod schema); on failure return `{ exitCode: 2, errorMessage }`.
   - Read source content from `ctx.config.sourcePath` (resolved against `ctx.context.workspaceDir` if relative). Reject if missing.
   - Probe `client.health()`; on failure return `errorFamily: "transient_upstream"` so the run loop retries.
   - Branch on `capability`:
     - **`generate_podcast`**: defaults `episodeProfile=solo_expert`, `speakerProfile="solo_expert"` (matches the live profile), `episodeName=basename(sourcePath)`. Optionally pre-create a source via `POST /api/sources` so the podcast has a content anchor. Call `POST /api/podcasts/generate` with `content=<markdown body>` (the API accepts inline content; using `notebook_id` is optional). Poll `GET /api/podcasts/jobs/{job_id}` until `completed`; read `episode_id` from the result. `GET /api/podcasts/episodes/{episode_id}/audio` → write to `<outputDir>/podcast.mp3` (atomic via `tmp + rename`).
     - **`generate_mind_map` / `generate_faq` / `generate_study_guide` / `generate_briefing`**: `ensureTransformations()`, `POST /api/sources` (text + title), then `POST /api/sources/{source_id}/insights` with the resolved `transformation_id`. Poll `GET /api/commands/jobs/{command_id}` until `completed`. `GET /api/sources/{source_id}/insights` → take the most recent matching insight, write `result.content` (markdown) to `<outputDir>/{capability}.md` with a small frontmatter block (`source_path`, `generated_at`, `transformation_id`, `source_id`).
   - Build `AdapterExecutionResult`: `exitCode: 0`, `summary: "Generated <capability> at <relative-path>"`, `resultJson: { capability, artifacts: [{ path, bytes, mimeType }], openNotebook: { sourceId, jobId, episodeId? } }`, `model: capability`, `provider: "open-notebook"`, `costUsd: 0`.

## Risk

- **R1 — Source path mismatch in the parent issue.** Issue body cites `vault/blogs/2026-04-30-notebooklm-as-a-learning-system/draft.md`; actual on-disk path is `vault/blogs/notebooklm-as-a-learning-system/draft.md` (139 lines, 1648 words). Mitigation: Executor uses the real path and notes the correction in the smoke report; Plan Reviewer should rubber-stamp the corrected path.
- **R2 — `mind_map`/`faq`/`study_guide`/`briefing` are not built-in insight kinds.** They must be seeded as custom `transformations` (idempotent POST on first execute). Mitigation: `transformations.ts` runs at the top of `execute()` and caches the resulting IDs per base URL. Risk surfaces if open-notebook resets its DB; ensureTransformations re-creates them automatically.
- **R3 — Podcast generation can exceed 5 min** for longer sources or under load. Mitigation: 8-min hard timeout, surface as `errorFamily: "transient_upstream"` so the run loop retries once, not as a permanent failure. Document the timing envelope in the README.
- **R4 — Auth surface unknown.** `OPEN_NOTEBOOK_API_KEY=local-dev` is in env, but `GET /api/auth/status` may report `enabled=false`. Mitigation: call `auth/status` at adapter init, only attach `Authorization` header when required.
- **R5 — Host network vs container network confusion.** Default base URL must be `http://open-notebook:5055`. If anyone runs the adapter outside the docker network (e.g. from `pnpm test` on the host), they must override via env. Mitigation: `testEnvironment()` makes the host/container DNS distinction explicit in its `info` checks.
- **R6 — Two host-side placeholder dirs exist**: `/app/adapters/notebooklm-driver/` (per issue) AND a clean home in `packages/adapters/notebooklm-driver/` (per upstream convention). We keep the real code in the latter to play well with `pnpm-workspace.yaml` + `tsc`. Mitigation: drop a redirect README in the placeholder so future agents grep-land on the right location.
- **R7 — Rollback.** If the smoke fails or production paperclip-server crashes on startup, revert is one-line: remove the matching record from `~/.paperclip/adapter-plugins.json` and `pnpm exec paperclip adapter list` to confirm gone, then restart paperclip-server. The package itself can stay in the workspace; only the registration controls discovery.
