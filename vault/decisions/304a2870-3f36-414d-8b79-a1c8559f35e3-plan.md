## Approach (1 chosen, alternatives rejected)

**Chosen: Rubric + skill update + lightweight audit script + targeted backfill (currently 0 fixes needed).**

Wire alt-text into the G0 BLOCK dimensions with concrete grep-able patterns, mirror the same rule into both author skills' "Definition of Done" checklists, ship a `scripts/audit-blog-alt.sh` that the Executor (and future Content Reviewer agents) can run against `vault/blogs/`, then verify the 14 live blogs produce a clean report. Backfill is only the supply-chain blog's three alts IF the audit flags them; current spot-check says no edits needed.

**Why this approach:**
- Cheapest path that closes the loop. The current live-site exposure is near-zero (no resolved hero/inline images render today), so the real ROI is preventing the next batch when image-gen unblocks. The cost is ~3 files of markdown + 1 small bash script.
- Audit-as-code (the bash script) means future drafts get checked automatically by the Reviewer instead of relying on the prose rubric being interpreted consistently.
- The `decorative: true` opt-in cleanly separates the WCAG "decorative = `alt=""`" rule from "missing alt = bug".

**Rejected: Type-level enforcement in `learnovaBeast/learnova-academy/src/lib/vault.ts`.** Forcing `alt: string` to be non-empty at parse time would surface failures at build time instead of at G0, which is later in the chain and harder to fix (the draft is already merged). Out of scope for this ticket; can be tracked separately if Reviewer compliance drifts.

**Rejected: Generate alt text in the Reviewer (auto-fix).** Violates the Reviewer's "never write or rewrite the draft yourself" rule at `content-reviewer/AGENTS.md:64-65`. The Reviewer must BLOCK, not patch.

## Risk

**Decorative vs meaningful confusion.** WCAG requires `alt=""` for purely decorative images so screen readers skip them — but an agent reading the rubric may interpret "must have descriptive alt" as "never empty," causing it to BLOCK legitimate decorative images. **Mitigation:** the rubric and both skills MUST explicitly say `alt=""` is permitted ONLY when paired with the `decorative: true` opt-in or a `<!-- decorative -->` marker. The audit script must whitelist those exact markers and never flag them. If Executor finds an existing legitimately-decorative image during backfill, it gets the opt-in marker, not a synthesized alt string.

**Secondary risk:** the audit script's heuristic regex for "generic alt" could over-fire on legitimate short alts (e.g., "Logo"). Mitigation: keep the generic-alt regex tight to the named one-word set listed in Step 1 and re-tune only if a real false-positive surfaces.
