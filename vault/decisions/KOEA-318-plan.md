# Plan: V3.8 — swap npm `hermes-paperclip-adapter` → workspace `@paperclipai/adapter-hermes-local`

## Goal

In `server/src/adapters/registry.ts`, replace the npm `hermes-paperclip-adapter@^0.3.0` import with the workspace `@paperclipai/adapter-hermes-local` package. After the swap, `cost_events` rows for Hermes runs must show real per-token costs from `hermes sessions export` instead of the bogus `$2024`-shaped values produced by the npm 0.3.0 stdout-regex parser.

This is the V3.8 follow-through on the residual issue called out in `vault/decisions/2026-05-02-hermes-cursor-durability.md` §"Known residual issues" item 1 ("Hermes adapter_failed cosmetic"). It is also Engineering Trio E2E test #4 (KOEA-317), so the implementation surface is intentionally small and bounded.

## Context

- The npm package `hermes-paperclip-adapter@0.3.0` parses Hermes cost from raw stdout via a `\$\d+` regex. Hermes occasionally emits literal `$N` strings inside model output (file paths, jq expressions, etc.) — these match the regex and write nonsense like `$2024` into `cost_events.cost_usd`.
- The workspace adapter `packages/adapters/hermes-local/` (already scaffolded but not wired in) reads cost from `hermes sessions export --session-id <id> -`, which emits a structured JSONL record with `actual_cost_usd / estimated_cost_usd / billing_provider / model`. This is the official source of truth and matches what Hermes' own dashboard shows.
- The workspace adapter already supports `ctx.authToken` natively (see `packages/adapters/hermes-local/src/server/execute.ts:235` — no cast needed), so the `executeHermesLocal as unknown as ServerAdapterModule["execute"]` workaround in `registry.ts:237` can be removed.
- The npm package is still consumed by `ui/src/adapters/hermes-local/index.ts` (only `parseHermesStdoutLine` + `buildHermesConfig` from `hermes-paperclip-adapter/ui`). **UI side is out of scope** for this ticket — leave the UI dep in `ui/package.json` untouched.

### Files to read first

- `server/src/adapters/registry.ts:71-82, 235-299` — current Hermes import + adapter wiring
- `server/src/__tests__/adapter-registry.test.ts:12-24` — vitest mock of the npm path
- `packages/adapters/hermes-local/src/server/index.ts` — current workspace exports (only `execute` + parse/runtime helpers)
- `packages/adapters/hermes-local/DESIGN.md` — V1 scope (skill injection intentionally deferred)
- `node_modules/.pnpm/hermes-paperclip-adapter@0.3.0/node_modules/hermes-paperclip-adapter/dist/server/{test,skills,detect-model,index}.d.ts` — npm 0.3.0 server-side surface (the source for ports below)

### Constraint: server export gap

`registry.ts` imports six symbols from `hermes-paperclip-adapter/server` and two from `hermes-paperclip-adapter`:

| Symbol | Used as | Workspace adapter has it? |
|---|---|---|
| `execute` | `hermesExecute` | ✅ |
| `testEnvironment` | `hermesTestEnvironment` | ❌ — must add |
| `sessionCodec` | `hermesSessionCodec` | ❌ — must add |
| `listSkills` | `hermesListSkills` | ❌ — must add |
| `syncSkills` | `hermesSyncSkills` | ❌ — must add |
| `detectModel` | `detectModelFromHermes` | ❌ — must add |
| `agentConfigurationDoc` | (root) | ✅ |
| `models` | (root) | ✅ |

So this is **not** a one-line import swap. The workspace adapter must grow four new server-side modules first; only then can the registry import path change cleanly.

## Approach (chosen)

Port the four missing exports into the workspace adapter as small, focused modules — keeping the same names and shapes the npm 0.3.0 package exposes, so the diff in `registry.ts` is purely a path rename. Then flip the import path, the package.json dep, and the test mock in lockstep.

For `listSkills` / `syncSkills`, port a no-op-skills implementation (return an empty `AdapterSkillSnapshot`). The workspace adapter's DESIGN.md §6 explicitly says "skill injection: not in V1 (Hermes uses its own skills)" and §7 lists skill injection as deferred to V2. The npm 0.3.0 package itself does the same thing — it just returns an empty list, since Hermes manages its own skill registry. We are matching prior behaviour, not regressing.

For `detectModel`, port the `~/.hermes/config.yaml` parser from npm 0.3.0 (`detect-model.ts`) verbatim. It is ~70 lines, regex-based, no YAML dep. The dashboard "detected model" tile depends on it.

For `sessionCodec`, port the validation/migration codec from npm 0.3.0 — it's a thin Zod-style schema that normalizes the `{ sessionId, cwd }` shape stored on `runtime.sessionParams`. The workspace `execute.ts` already reads from this exact shape, so the codec just makes it official.

For `testEnvironment`, port the npm 0.3.0 implementation (binary resolution + `hermes --version` smoke + `~/.hermes/auth.json` presence check). This is what populates the dashboard adapter "OK / FAIL" badge.

## Approaches rejected

- **Stub the four missing exports as no-ops directly in `registry.ts`.** Rejected: hides the gap, leaves the workspace adapter incomplete, and silently regresses the dashboard adapter-status check + model-detection tile. The workspace package is supposed to be a drop-in for the npm package — fixing the gap once in the package is the right level.
- **Keep the npm dep installed and import only `execute` from the workspace.** Rejected: defeats the whole point. The npm package's stdout-regex cost parser would still run for every other code path that touches it (and we'd be carrying two copies of the Hermes adapter type surface). Cleaner to swap fully.
- **Port `listSkills` / `syncSkills` with real skill-pack symlinking (matching `claude_local` / `opencode_local`).** Rejected: out of scope. Hermes uses its own skill registry (`~/.hermes/skills/`), not Paperclip's. Symlink-injecting Paperclip skills into Hermes is its own design problem (the DESIGN.md V2 task). For V3.8 we just need parity with the existing npm behaviour, which is empty-snapshot.
- **Bump the workspace adapter's `package.json` version to `0.3.0` to signal feature parity.** Rejected: it stays at `0.1.0` (no consumers outside this monorepo, no semver promise needed).

## Risk

- **Skill snapshot shape drift.** If the empty `AdapterSkillSnapshot` literal in step 5 doesn't match the union exactly (e.g. discriminator field rename in a recent `adapter-utils` change), `pnpm --filter @paperclipai/server typecheck` will fail downstream of the import swap. Mitigation: copy the empty-snapshot literal from `packages/adapters/claude-local/src/server/skills.ts` (or similar sibling) — those packages already type-check against the same `adapter-utils` version.
- **`detectModel` return-shape mismatch.** Workspace `DetectedModel` has `baseUrl + apiMode + source: "config"` while `ServerAdapterModule.detectModel` expects `{ model, provider, source, candidates? }`. Today `registry.ts:298` calls it as `() => detectModelFromHermes()` and returns whatever it returns — TypeScript will narrow on the actual return type. Mitigation: in step 9 wrap the call as `detectModel: async () => { const r = await detectModelFromHermes(); return r ? { model: r.model, provider: r.provider, source: r.source } : null; }` if typecheck complains.
- **Cost-row anomaly persists post-swap.** If the smoke test still shows `$2024`-shape rows after the swap, the bug is not in the adapter parser but in upstream stdout — file a follow-up against Hermes itself, do not patch around it. Mitigation: keep the npm `0.3.0` package installed in the lockfile cache for ~24 hours (it'll be GC'd by the next `pnpm install --frozen-lockfile`) so we can `pnpm --filter @paperclipai/server install hermes-paperclip-adapter@0.3.0 --save` to revert quickly.
- **Container rebuild needed.** `infra/docker-compose.koenig.yml` builds the server image via `pnpm install` — the workspace symlink is honoured inside the image as long as the build context includes `packages/adapters/hermes-local`. If the Dockerfile uses a narrower copy step, the image will fail to start. Mitigation: confirm the Dockerfile copies `packages/adapters/**` in the build context before rebuilding (`grep -n "COPY packages" Dockerfile`).

## Out of scope

- **UI-side dep swap.** `ui/src/adapters/hermes-local/index.ts` continues to import from `hermes-paperclip-adapter/ui` (the `parseHermesStdoutLine` + `buildHermesConfig` helpers). The npm `0.2.0` dep stays in `ui/package.json`. Filing a follow-up `KOEA-3xx — UI hermes adapter swap` is welcome but not blocking for V3.8.
- **Real skill-pack symlinking** for Hermes (the DESIGN.md V2 task). Empty snapshot is the V3.8 contract.
- **Cost-row backfill.** Existing `$2024`-shape rows in `cost_events` from before the swap stay as-is; treat them as known-bad until a separate cleanup script is written.
- **Hermes binary durability** — already shipped in V3.6 (`vault/decisions/2026-05-02-hermes-cursor-durability.md`). This swap assumes `hermes` resolves on PATH inside the running container.
- **`registry.ts` refactor**, including untangling the `normalizeHermesConfig` + `authGuardPrompt` env-patching into the workspace adapter's `execute` itself. Possible later cleanup; not required for the bug fix.
