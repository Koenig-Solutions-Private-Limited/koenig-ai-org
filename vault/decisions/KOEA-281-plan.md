# Plan: KOEA-281 — Fix 404s, catalog/learn route mismatch

## Goal

Eliminate 404s when navigating from `/catalog` to `/learn/<slug>` by switching `catalog/page.tsx` from the hardcoded `fixtures.ts` placeholder slugs to the same vault-backed source (`listAllCourses()`) that `learn/[slug]/page.tsx` already uses. After this change, every catalog tile resolves to a real course page generated by `generateStaticParams`.

## Context

- Files to read first:
  - `learnovaBeast/learnova-academy/src/app/catalog/page.tsx:1-135` — current monolithic `"use client"` page
  - `learnovaBeast/learnova-academy/src/app/learn/page.tsx:1-196` — already-correct vault-backed pattern to mirror
  - `learnovaBeast/learnova-academy/src/app/learn/[slug]/page.tsx:26-37` — `generateStaticParams` defines the universe of valid slugs
  - `learnovaBeast/learnova-academy/src/lib/courses.ts:178-202` — `listCourseSlugs()` filters by `outline.md` presence; `listAllCourses()` returns vault `Course[]`
  - `learnovaBeast/learnova-academy/src/lib/fixtures.ts:4-31, 86-278` — `VendorId`, `CourseLevel`, `CourseType`, `vendors`, `Course` shape (consumed by `CourseCard`)
  - `learnovaBeast/learnova-academy/src/components/_shared/content.tsx:368-513` — `CourseCard` is `"use client"`, expects `fixtures.Course`
- Vault state (verified):
  - 6 courses with `outline.md` (all `status: outline-draft-for-review`, `level: Builder`):
    `claude-opus-47-from-zero`, `gemini-enterprise-agent-platform-hands-on-tour`, `gemini-enterprise-agents`, `mcp-from-first-principles-to-production`, `picking-a-frontier-model-2026-q2`, `production-agents-claude-agent-sdk-mcp-connector`
  - `claude-tool-use-from-zero/` exists with one chapter file (`07-creative-connectors.md`) but **no `outline.md`** → already filtered out by `listCourseSlugs()`. No action needed for catalog: it will simply not appear post-fix. Creating the outline is a content-team task, not part of this ticket.
  - `vendor_tag` values present in vault: `anthropic`, `google`, `community`. `community` is **not** in current `VendorId` union — must be handled.
- Constraints:
  - Budget $0.80 (plan + execute).
  - Don't change `CourseCard`'s prop type — many callers (`/`, `/catalog`) depend on `fixtures.Course`. Map at the server boundary instead.
  - Keep `force-static` semantics — catalog is build-time SEO surface (JSON-LD itemList).

## Approach (chosen)

Split `catalog/page.tsx` into a thin server wrapper + a client child. The server component calls `listAllCourses()`, maps each vault `Course` into the existing `fixtures.Course` shape via a local `toCatalogCard()` helper, and passes the array as a prop to a new `<CatalogFilters>` client component that owns search/filter/sort state and renders the existing `<CourseCard>` grid + JSON-LD. This is the minimum-blast-radius fix: it reuses the proven `learn/page.tsx` pattern, leaves `CourseCard` and shared types untouched, and makes catalog automatically inherit any future vault additions. Mapping happens in **one** place (the server file) — Executor can later promote it to `lib/courses.ts` if a third caller needs it (out of scope here).

## Approaches rejected

- **Change `CourseCard` to accept vault `Course` directly.** Touches `/` (home page) and risks a cascading refactor outside ticket scope; also forces vault to invent fields (`cover`, `popularity`, `learners`) that don't belong on the content side.
- **Make catalog read fixtures but filter against `listCourseSlugs()`.** Hides the bug instead of fixing it — tiles disappear without anyone updating fixtures, and the catalog still drifts from vault. Defeats the "permanent fix" goal stated in the parent ticket.

## Steps

2. **Create `src/app/catalog/catalog-client.tsx`** as a `"use client"` component that takes `{ courses: Course[] }` (from `@/lib/fixtures`) as props and contains everything currently in `catalog/page.tsx` from line 21 (`useState` block) through the JSX `</main>` plus the `Select` helper — i.e., search/vendor/level/type/sort filters and the `<CourseCard>` grid. No data fetching here.
3. **Rewrite `src/app/catalog/page.tsx`** as a server component (no `"use client"`). It (a) calls `listAllCourses()`, (b) maps results via a local `toCatalogCard(c: Course): fixtures.Course` helper, (c) emits the `itemListLd` JSON-LD using the mapped slugs, (d) renders `<TopBar />` and `<CatalogFilters courses={mapped} />`. Keep `export const dynamic = "force-static"` semantics implicitly via no dynamic APIs.
4. **Implement `toCatalogCard()` mapping** in `catalog/page.tsx`:
   - `id`, `slug` ← `slug`
   - `title` ← `title`
   - `tagline` ← `target_audience ?? learning_outcomes[0] ?? ""`
   - `vendor` ← `vendor_tag` cast to `VendorId` (now includes `community`)
   - `level` ← `level` cast to `CourseLevel` (vault values are `Beginner` | `Builder` | `Professional` per existing convention; default to `Builder` if unrecognized)
   - `type` ← `"interactive"` (vault has no equivalent; same default the existing data already uses for most rows)
   - `duration` ← `total_duration_min`
   - `updated` ← `today` (imported from fixtures) — used only for sort
   - `popularity` ← `0` (no signal yet; sort is "newest" by default so popularity sort will be a stable no-op)
   - `chapters` ← `chapter_count || chapters.length`
   - `learners` ← `0`
   - `badge` ← `status === "outline-draft-for-review" ? "Draft" : status === "outline-g0-passed" ? "In review" : "Live"`
   - `cover` ← vendor → cover map: `anthropic: "teal"`, `openai: "green"`, `google: "blue"`, `meta: "amber"`, `mistral: "rose"`, `community: "amber"`
5. **Verify static output**: `pnpm --filter learnova-academy build` (or `npm run build`). Confirm:

   - Each tile's `<a href="/learn/...">` resolves to a `generateStaticParams`-emitted page (no 404).
6. **Manual smoke** in `pnpm dev`: visit `/catalog`, click each of the 6 tiles in turn, confirm the course landing page renders. Filter by Vendor=Google → 2 tiles. Filter by Vendor=Anthropic → 3 tiles. Filter by Vendor=Community → 1 tile.

## Risk

- **Type-narrowing on `vendor_tag` / `level`**. Vault `vendor_tag: string` and `level: string` are wider than `VendorId` / `CourseLevel`. A future vault entry with an unknown value would slip through unchecked. **Mitigation**: in `toCatalogCard()`, hard-code the recognized sets and fall back to `anthropic` / `Builder` with a `console.warn` for unknowns — small enough to keep in the same file, surfaces drift early without breaking the build.
